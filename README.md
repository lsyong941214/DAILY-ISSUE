# DAILY-ISSUE

GitHub Actions로 돌아가는 개인 알림·콘텐츠 자동화 모음입니다.

| 워크플로 | 하는 일 | 실행 시점 |
| --- | --- | --- |
| `.github/workflows/kakao-briefing.yml` | `briefing.txt` 내용을 카카오톡으로 전송 | `briefing.txt`가 main에 push될 때 |
| `.github/workflows/youtube-kakao.yml` | 유튜브 새 영상 → 카카오톡 알림 + 티스토리 포스팅 자료 생성 | 매일 오전 7시(KST) + 수동 실행 |

## 유튜브 새 영상 루틴

대상 채널: **소수몽키** ([@sosumonkey](https://www.youtube.com/@sosumonkey), `UCC3yfxS5qC6PCwDzetUuEWg`)

### 동작 순서

매일 아침 한 번, **가장 최근 영상 하나만** 확인합니다.

1. **최신 영상 확인** — 유튜브 RSS 피드(`feeds/videos.xml`)의 맨 위 영상 하나를 봅니다.
   유튜브 API 키가 필요 없습니다. 피드가 막히면 재시도한 뒤, 그래도 안 되면
   채널 페이지에서 최신 영상을 찾습니다.
2. **이미 보낸 영상이면 아무것도 하지 않습니다.** 메시지를 보내지 않고 조용히 끝납니다.
3. **자막 확보** — 영상의 자막(자동 생성 포함)을 받아옵니다. 아래 두 단계 모두 이걸 근거로 씁니다.
4. **새 영상이면 카카오톡 브리핑** — 자막을 근거로 **이슈 → 영향 → 관점** 순으로 정리해 보냅니다.
5. **티스토리 자료 생성** — 자막 내용을 바탕으로 Gemini가 검색으로 사실관계를 확인해
   포스팅 원고를 만들어 저장소에 커밋합니다. (별도 알림은 보내지 않습니다)

지난 영상을 소급해서 보내지 않습니다. 하루 사이에 영상이 여러 개 올라와도 **가장 최근 것 하나만** 처리합니다.

카카오톡 메시지 예시:

```
🇺🇸 소수몽키 · 08/17 20:00
미국의 중국 메모리 때리기 본격 시작?

📌 이슈
美 상무부, 중국 메모리 3사 수출 통제 명단 추가
발효 시점은 내년 1분기로 예고

📈 영향
· 마이크론·SK하이닉스: 중국 공급 축소로 단가 반등 기대
· 반도체 장비주: 중국 매출 비중만큼 실적 하방

🧭 관점
공급 축소가 실적에 반영되기까지 시차가 있음
단기 주가보다 재고·가동률 지표를 확인할 것

https://youtu.be/XXXXXXXXXXX      [영상 보기 버튼]
```

**정확한 수치 나열이 아니라 "누가 무엇을 했고, 어디에 어떤 영향인가"**에 초점을 둡니다.
종목·티커는 영상에서 언급됐거나 검색으로 확인된 것만 씁니다.
카카오가 긴 글을 거부하면 자동으로 나눠 보냅니다.

### 티스토리 자료

기존 경제 이슈 자료와 **같은 폴더 규칙·같은 문서 형식**으로 `YYYY-MM-DD/` 아래에 생성됩니다.

| 파일 | 용도 |
| --- | --- |
| `<제목>.html` | 브라우저로 열어 미리보기. 티스토리 **HTML 모드**에 통째로 붙여넣어도 됩니다 |
| `<제목>_붙여넣기용_소스.txt` | 본문 `<div>`만 담긴 파일. 티스토리 편집기에 그대로 붙여넣기 |
| `<제목>_네이버용.txt` | 같은 내용을 네이버 블로그 문체(구어체·짧은 줄바꿈)로 다시 쓴 텍스트 |

작성 규칙은 `tistory-post-from-notes` 스킬의 규칙을 자동화 스크립트에 옮겨 담았습니다.
소제목은 전부 `<h1>`(인라인 font-size로 위계), 문단 3~4줄, 본문 1,500~2,500자,
정부·공공기관 원자료를 최우선 출처로 쓰고 **영상이 인용한 원자료를 찾아서 답니다.**

글에 들어가는 것:

- 영상 임베드(iframe)와 출처 표기
- **무슨 일이 있었나 → 어디에 어떤 영향인가 → 투자자는 무엇을 봐야 하나** 흐름의 소제목 3~5개
- 어려운 용어 설명 박스
- **자막에서 확인한 영상의 실제 발화 내용** + 검색으로 확인한 수치와 출처 링크 (확인되지 않은 숫자는 쓰지 않도록 지시돼 있습니다)
- "한 줄 정리" 박스(기억할 핵심 3가지)
- 참고 자료 목록, 투자 권유가 아니라는 면책 문구, 해시태그 5~8개

영상 내용을 그대로 받아쓰는 것이 아니라, 영상이 던진 주제를 출발점으로 사실관계를 정리하는 방식입니다. **초안이므로 발행 전에 수치와 출처를 한 번 확인하시는 걸 권합니다.**

#### 자동 점검

생성 직후 스킬의 확인 목록을 스크립트로 검사합니다. `h2`~`h6` 소제목과 네이버용에 섞인
HTML 태그·엔티티는 **자동으로 고치고**, 나머지는 로그에 `[check]` 로 남깁니다.

- 붙여넣기용 본문이 `<div>`로 시작해 `</div>`로 끝나는지
- 소제목이 전부 `<h1>`이고 여닫는 개수가 맞는지
- `<style>`·`<script>`·`class=` 가 없는지
- 열고 닫는 태그가 맞는지 (`html.parser`)
- 표의 열이 4개 이하인지
- 채우지 않은 `[대괄호]` 자리표시가 없는지
- 네이버용이 순수 텍스트인지

### 필요한 Secrets

`Settings → Secrets and variables → Actions → New repository secret`

| 이름 | 필수 | 설명 |
| --- | --- | --- |
| `KAKAO_CLIENT_ID` | ✅ | 카카오 앱의 REST API 키 (기존 브리핑 워크플로와 동일) |
| `KAKAO_CLIENT_SECRET` | ✅ | 카카오 앱 Client Secret |
| `KAKAO_REFRESH_TOKEN` | ✅ | `talk_message` 동의를 받은 리프레시 토큰 |
| `GEMINI_API_KEY` | ✅ (요약·티스토리 자료용) | [Google AI Studio](https://aistudio.google.com/apikey)에서 발급. **무료 티어**라 결제수단 등록이 필요 없습니다 |

`GEMINI_API_KEY`가 없어도 카카오톡 알림은 그대로 동작합니다.
요약이 영상 설명 앞부분으로 대체되고, **티스토리 자료 생성만 건너뜁니다.**

### 자막을 먼저 쓰는 이유

영상 파일을 그대로 모델에 넘기면 입력 토큰을 매우 많이 쓰지만, **자막 텍스트는 같은 내용을
훨씬 적은 토큰으로 담습니다.** 그래서 기본 경로는 자막이고, 자막을 못 받았을 때만
영상을 직접 분석합니다(`TISTORY_USE_VIDEO=0`이면 이 단계도 건너뜁니다).

자막을 못 받는 경우도 있습니다 — 자막이 아예 없는 영상, 유튜브가 러너 IP를 막은 경우 등입니다.
이때는 조용히 다음 방법으로 넘어가고 루틴은 계속 진행합니다.

무료 티어에는 분당·일일 요청 한도가 있습니다. 한도(429)에 걸리면
잠시 기다렸다 다시 시도하고, 그래도 안 풀리면 **계정에서 쓸 수 있는 다른 모델로 자동 전환**해
다시 시도합니다(브리핑·원고 모두). 그래도 막히면 영상 분석 없이 제목·설명만으로 원고를 만듭니다.
그마저 안 되면 **원고만 건너뛰고 워크플로는 정상 종료**합니다(카톡 알림은 이미 나간 뒤).
카카오톡 브리핑도 같은 이유로 실패하면, AI 분석 대신 영상 설명란 앞부분을 그대로 보냅니다 —
평소보다 메시지가 부실하다면 이 경로를 탄 것이니 [Google AI Studio](https://aistudio.google.com/apikey)에서
`GEMINI_API_KEY`의 실제 한도(모델별 RPD)를 확인해 보세요.
한도가 풀린 뒤 force 옵션으로 다시 실행하면 원고를 만들 수 있습니다.

### 수동 실행

`Actions → YouTube to KakaoTalk → Run workflow`로 언제든 돌릴 수 있습니다.
기록에 없는 최신 영상이 있으면 그 자리에서 처리하고, 없으면 아무 일도 일어나지 않습니다.

실행 버튼에 옵션 두 개가 있습니다.

| 옵션 | 동작 |
| --- | --- |
| **force** | 이미 보낸 영상이어도 최신 영상을 다시 처리합니다 (카톡도 다시 발송) |
| **drafts_only** | **카톡은 보내지 않고** 티스토리 원고만 다시 만듭니다. 한도(429)로 원고가 빠졌을 때 쓰세요 |

### 조정할 수 있는 값

워크플로의 `env`로 바꿀 수 있습니다.

| 환경변수 | 기본값 | 설명 |
| --- | --- | --- |
| `YOUTUBE_CHANNEL_ID` | `UCC3yfxS5qC6PCwDzetUuEWg` | 감시할 채널 ID |
| `YOUTUBE_HANDLE` | `sosumonkey` | 채널 ID로 조회가 실패하면 이 핸들로 ID를 다시 찾습니다 |
| `YOUTUBE_CHANNEL_NAME` | `소수몽키` | 메시지·글에 표기할 채널 이름 |
| `YOUTUBE_BRIEF_LIMIT` | `420` | 카카오톡 브리핑 본문 최대 글자 수 |
| `GEMINI_MODEL` | `gemini-3.6-flash` | 요약·글 생성에 쓰는 모델. 모델이 바뀌면 API 안내와 모델 목록을 보고 자동으로 대체합니다 |
| `TISTORY_USE_VIDEO` | `1` | **자막을 못 받았을 때만** 영상을 직접 분석할지. 영상 분석은 토큰을 훨씬 많이 쓰므로, 한도가 빠듯하면 `0`으로 두세요 |

실행 시각은 워크플로의 `cron`으로 바꿉니다. 현재 `"0 22 * * *"`(UTC) = **한국 시간 오전 7시**입니다.
UTC 기준이라 한국 시간에서 9시간을 빼서 적으면 됩니다 (오전 8시 → `"0 23 * * *"`).
GitHub Actions 스케줄은 몇 분에서 수십 분 지연될 수 있습니다.

### 스크립트 구성

| 파일 | 역할 |
| --- | --- |
| `.github/scripts/youtube_kakao.py` | 최신 영상 확인 → 중복 판별 → 카카오톡 전송 → 상태 기록 |
| `.github/scripts/tistory_post.py` | 새 영상 → 검색 취재 → 티스토리/네이버 원고 생성 + 형식 자동 점검 |
| `.github/scripts/youtube_transcript.py` | 영상 자막(자동 생성 포함) 받아오기 |
| `.github/scripts/gemini_client.py` | Gemini API 호출 (표준 라이브러리만 사용) |
| `.github/scripts/http_util.py` | 유튜브 요청 공용 헬퍼 (브라우저 UA, 재시도) |
| `.github/scripts/kakao_client.py` | 카카오 토큰 갱신 및 '나에게 보내기' 전송 |

외부 패키지를 설치하지 않으므로 워크플로에 별도 의존성 설치 단계가 없습니다.

### 알아둘 점

- 스케줄 워크플로는 **기본 브랜치(main)에 있어야** 동작합니다.
- 카카오 리프레시 토큰은 유효기간이 있습니다(약 60일, 사용 시 자동 갱신). 만료되면 재발급 후 Secret을 갱신하세요.
- 카카오 '나에게 보내기'는 텍스트 길이 제한이 있습니다. 한 통으로 보내다 거부되면 자동으로 나눠 보냅니다.
- 영상이 없거나 이미 보낸 영상이면 **메시지를 보내지 않습니다.**
- 유튜브 RSS에는 쇼츠와 예정된 라이브도 함께 올라옵니다. 제외가 필요하면 알려주세요.
- 짧은 시간에 여러 번 수동 실행하면 유튜브가 일시적으로 피드를 막을 수 있습니다(404). 하루 1회 정기 실행에서는 거의 문제되지 않습니다.
