# Apple 메모 앱에서 내용 읽어오기

Apple 메모(Notes)의 데이터는 암호화된 CoreData 저장소에 있어 파일로 읽을 수 없다. bash 샌드박스는 Linux라 macOS 앱에 접근할 수도 없다. 따라서 **화면을 보고 읽는 방법(computer-use MCP)이 유일한 경로**다. 느리지만 확실하다.

## 준비

computer-use 툴이 deferred 상태면 한 번에 전부 로드한다 (하나씩 부르면 왕복이 낭비된다):

```
ToolSearch: { query: "computer-use", max_results: 30 }
```

그다음 접근 권한을 요청한다. **표시 이름 대신 번들 ID를 쓴다:**

```
request_access(apps: ["com.apple.Notes"])
```

번들 ID를 쓰는 이유: 한국어 macOS에서 앱 이름은 "메모"로 표시되는데, `"Notes"`로 요청하면 "설치되어 있지 않다(did you mean 메모?)"는 응답이 오고, 안내대로 `"메모"`로 다시 요청해도 같은 오류가 반복된다. 한글 문자열 정규화(NFC/NFD) 차이로 이름 대조가 실패하기 때문으로 보인다. `com.apple.Notes`는 한 번에 통과한다.

승인 후 `open_application("com.apple.Notes")` 도 같은 번들 ID로 호출한다.

메모 앱은 tier "full"로 승인되므로 클릭·타이핑·스크롤이 모두 가능하다.

참고: 시스템 권한(손쉬운 사용·화면 기록)이 아직 없으면 `request_access`가 권한 안내 오류를 돌려준다. 이때는 사용자에게 Claude 데스크톱 앱에서 두 권한을 허용해 달라고 요청한 뒤 다시 시도한다.

## 화면 구조

메모 앱은 보통 3단 레이아웃이다:

```
┌──────────┬──────────────┬─────────────────────┐
│ 폴더 목록 │  메모 목록    │   메모 본문          │
│ (사이드바)│ (제목+미리보기)│                     │
└──────────┴──────────────┴─────────────────────┘
```

사이드바가 접혀 있으면 좌측 상단 사이드바 토글 버튼을 클릭하거나 `⌥⌘S`로 편다.

## 절차

### 1. 앱 열고 상태 확인

```
open_application("com.apple.Notes")
screenshot()
```

첫 스크린샷으로 레이아웃, 폴더 목록, 현재 선택된 메모를 파악한다. 여기서 본 것을 근거로 다음 클릭 좌표를 정한다 — 좌표를 추측하지 말고 항상 방금 찍은 스크린샷에서 읽는다.

### 2. 카테고리 폴더 찾기

사이드바에서 요청받은 카테고리와 일치하는 폴더를 찾는다.

- **정확히 일치**: 바로 클릭
- **유사한 것만 있음** (예: 요청 "부동산", 폴더 "부동산_스터디"): 그 폴더가 맞는지 사용자에게 확인
- **없음**: 전체 폴더 목록을 보여주고 어디를 볼지 되묻는다. 검색(`⌘F` 또는 상단 검색창)으로 카테고리 키워드를 넣어 다른 폴더에 흩어져 있는지도 확인해 보고 결과를 함께 알린다

폴더가 접힌 계층 구조일 수 있으니 상위 폴더의 펼침 화살표도 확인한다.

### 3. 메모 목록 확인

폴더를 클릭하면 가운데 열에 메모 목록이 뜬다. 스크린샷으로 제목과 수정 날짜를 읽는다.

- 메모가 1개면 바로 진행
- 여러 개면 **제목과 날짜 목록을 사용자에게 보여주고** 어느 것을 쓸지, 아니면 전부 묶을지 확인한다. 최근 것만 골라 진행하지 않는다 — 사용자가 오래된 메모를 염두에 뒀을 수 있다

### 4. 본문 읽기

메모를 클릭하면 우측에 본문이 뜬다.

**읽는 요령:**

- `screenshot()` 으로 보이는 부분을 읽는다. 스크린샷은 이미지로 직접 해석할 수 있으니 OCR 도구는 필요 없다
- 본문이 화면보다 길면 `scroll`로 아래로 내리며 **여러 번** 스크린샷을 찍는다. 스크롤 시 겹치는 구간이 생기도록 조금씩 내려야 중간 줄이 누락되지 않는다
- 스크롤이 끝에 닿았는지 확인: 마지막 두 스크린샷이 동일하면 끝이다
- 창이 좁아 줄바꿈이 심하면 `⌘M` 해제 후 창을 최대화하거나, 우측 본문 영역이 넓어지도록 사이드바를 잠시 접는다

**숫자·고유명사 확인:**

시세, 금리, 퍼센트, 기업명, 지역명은 글 전체의 신뢰가 걸린 부분이다. 스크린샷에서 흐릿하거나 자릿수가 헷갈리면 `zoom`으로 해당 영역을 확대해 다시 확인한다. 추측해서 넘어가면 안 된다.

읽은 결과가 애매하게 남는 항목이 있으면, 그 항목은 "메모 판독 불확실"로 표시해 두고 2단계 웹 검증에서 실제 값과 대조한다. 웹에서 확인된 값이 있으면 그것을 쓰고, 사용자에게 "메모에는 X로 보였는데 실제로는 Y였습니다"라고 알린다.

### 5. 원문 보존

읽어낸 내용을 **요약하지 말고 그대로** 정리해 둔다. 줄바꿈, 순서, 사용자가 쓴 표현을 유지한다.

이유: 다음 단계에서 "메모가 이렇게 말했는데 확인해보니 이랬다"를 비교해야 한다. 요약해 버리면 무엇이 틀렸는지 짚어줄 수 없고, 사용자가 그 메모를 어디서 잘못 알았는지 배울 기회가 사라진다.

## 흔한 문제

| 증상 | 대처 |
|---|---|
| 잠금 메모(자물쇠 아이콘) | 사용자에게 직접 잠금 해제를 요청한다. 비밀번호를 묻거나 입력하려 하지 않는다 |
| 폴더가 iCloud 동기화 중 | 잠시 기다렸다가 다시 스크린샷. 계속 안 되면 사용자에게 알린다 |
| 메모에 첨부 이미지/스캔 문서가 있음 | 스크린샷으로 보이는 만큼 읽고, 안에 텍스트가 있으면 그것도 읽는다. 해석이 어려우면 사용자에게 내용을 물어본다 |
| 클릭이 안 먹음 | 메모 앱이 최전면인지 확인. `open_application`으로 다시 앞으로 가져온 뒤 재시도 |
| 스크린샷에 다른 앱 창이 겹침 | 메모 창을 클릭해 활성화하거나 최대화 |

## 하지 말 것

- 메모 내용을 **수정·삭제하지 않는다.** 이 스킬은 읽기 전용이다. 실수로 본문에 타이핑되지 않도록, 본문 영역을 클릭할 때는 텍스트 커서가 들어가는 점을 유의한다 (스크롤과 스크린샷만으로 충분하다면 본문 클릭 자체를 피한다)
- 잠긴 메모의 비밀번호를 추측하거나 입력하지 않는다
- 요청받은 카테고리 외의 메모를 들춰보지 않는다. 사적인 내용이 있을 수 있다
